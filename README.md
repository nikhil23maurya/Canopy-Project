# Canopy

Canopy is a browser-based file compressor and restore tool for an Analysis and Design of Algorithms project at the Faculty of Technology, University of Delhi. It uses canonical Huffman coding to compress a file into a `.huf` archive and recover the original bytes exactly. Files are processed on the device. The maximum input size is 24 MiB.

The [public Netlify demo](https://canopy-project.netlify.app/) runs the earlier Canopy build and downloads `.huff` archives. This repository contains the benchmarked `.huf` build. Use the local launcher below to test this build.

## Run locally

Use Python 3 from the project directory:

```sh
python3 serve.py
```

The launcher opens the local site in your browser and prints its address. On Windows, double-click `Start_Canopy.bat`.

Choose **Compress**, select a file or a bundled sample, and download the resulting `.huf` archive. On **Restore**, open that archive to recover the original file. Compare the input and archive sizes before sharing. Small, high-entropy or already compressed files can produce larger archives.

## How it works

1. Count the input byte frequencies and repeatedly merge the two lowest-frequency nodes.
2. Assign canonical Huffman codes from the resulting code lengths.
3. Write a header with the original size, code lengths and CRC32, followed by the packed payload.
4. Rebuild the codebook on restore, decode the payload and verify CRC32.

## Source and test inputs

All bundled test inputs are synthetic. The GZIP fixture contains the same 720 device-log records generated by `site/samples.mjs`.

| Path | Contents |
| --- | --- |
| [site/codec.mjs](site/codec.mjs) | Greedy min-heap, canonical codes, bit packing and CRC32 verification |
| [site/worker.mjs](site/worker.mjs) | Browser Web Worker for compression and restore |
| [site/samples.mjs](site/samples.mjs) | Deterministic device logs, telemetry CSV, uniform binary and tiny text |
| [site/assets/device-logs.txt.gz](site/assets/device-logs.txt.gz) | Bundled precompressed test input |
| [benchmarks/presentation-results.json](benchmarks/presentation-results.json) | Recorded measurements presented in the slide deck |

## Reproduce the results

Run the benchmark with Node.js 24:

```sh
node benchmarks/run.mjs
```

The benchmark reports median compression and restore time over seven runs per input size, using repeated device logs from 256 KiB to 4 MiB. It compares archive sizes with GZIP and checks exact recovery, boundary handling, corruption rejection, and optimal payload cost on small inputs. Timing depends on hardware and runtime.
